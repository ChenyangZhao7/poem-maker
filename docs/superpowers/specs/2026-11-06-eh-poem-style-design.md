# EH-Poem-Style 设计文档

日期：2026-11-06
状态：已批准（v3，诗词均用中华新韵；风格卡人工审查；默认全部 56 首 + 整句查重）

## 1. 意图与原因

用户有 56 首自己写的完整作品（原文件 57 条，含 1 首重复）：其中 11 首词，其余为诗，均有题目。希望做到：用自然语言描述内容，生成**古体诗、律诗、词**，且读起来是用户自己的风格；随着使用，逐步积累语料，最终可能演化成"自己的诗词模型"。

现有做法（收集几百首后微调）与人类创作节奏不符：一年 50 首已是较高产量，等到几百首需要很多年，且模型会换代。因此本项目不把"够不够训练"当门槛，而是：

- **v1 不训练任何模型。**
- 用少量示例 + 显式风格卡，让通用大模型"指向"用户风格。
- 用独立的格律校验器保证硬约束，模型不达标就带着具体错误重试。
- 把每次生成、每次人工修改都沉淀为语料，为将来的可选微调积累数据。

核心原则：**薄模型，厚资产。** 依赖模型的部分做到最薄（可替换），属于用户的部分做到最厚（诗、词谱、规则、偏好记录都不依赖任何模型）。

## 2. 目标

1. 输入一段白话描述 + 体裁，输出对应体裁的诗；词需另给词牌名与平仄谱。
2. 分体裁校验：**诗只校验押韵与句数/字数**（不查平仄）；**词按词牌谱严格校验**平仄、句读、韵位与韵部。诗、词都用**中华新韵**。
3. 风格接近用户 56 首示例（用词、意象、句法、情感基调）。
4. 新增一个词牌只需粘贴"词牌名 + 谱子"，几分钟内可用。
5. 每次生成、每次人工取舍都自动落盘，语料可持续增长。
6. 模型供应商可替换（任何 OpenAI 兼容接口）。
7. 同一请求可在多套模型配置间对比（先接 DeepSeek V4.1 与本地模型两套），并排看输出与校验结果。

## 3. 非目标

- v1 不做微调/LoRA 训练。
- 不做通用聊天助手。
- 不做云端服务、多用户、移动端。
- 不自动从语料中"发现"词牌。
- 诗不校验平仄、粘对、孤平、三平调与对仗（按用户决定，v1 只查押韵）。
- 不还原中古音、不区分入声；诗、词都以现代普通话读音为准。
- 不处理现代诗、散文诗。

## 4. 反目标

以下情况视为失败，即使程序能跑：

- **合格律但不像用户**：读起来是任何人的诗。
- **像用户但破格**：诗的押韵或句数/字数、词的平仄/韵/句读有明显错误。
- 必须攒够几百首才能启动。
- 绑定单一模型厂商，换模型要改代码。
- 用户改过的字没有被记录，下次又从零开始。

## 5. 约束

- 运行环境：Windows，本地。
- 算力：不假设本地 GPU；生成走远程 API。
- 语料：56 首完整作品（11 首词），带题目。多数诗不合近体平仄、也不合平水韵，**只能作风格样本，不能作格律范本**。
- 用户会临时提供词牌名与惯用平仄谱，格式大致为 `⊙平⊙仄仄平平（韵）` 一类。
- 韵书：诗、词都用**中华新韵**。诗只查押韵、声调不限；词按谱查平仄与韵部。
- 词的多音字平仄按**整句上下文的最常用读音**判定（pypinyin 首选），不为了合谱改用生僻读音。
- 词牌有多体时，默认取**最常用正体**；用户语料中出现过的体优先（如江城子取单调 35 字）。
- 用户以中文交流，界面与提示词以中文为主。

## 6. 方案

### 6.1 考虑过的三种做法

**A. 提示词 + 格律校验 + 重试（采用）**

56 首做成风格卡与示例常驻上下文；模型生成后由脚本校验——诗查押韵与句数/字数，词逐字查词牌谱；不合格则把具体错误回传重试。

- 优点：56 首即可用；硬约束由代码兜底；风格层将来可整体替换为微调。
- 代价：每次请求携带风格包（可缓存）；校验器需自行实现。

**B. 约束解码 / 模板填词**

把平仄谱变成搜索约束，只在合律字中选，或按词牌模板逐句填。

- 优点：格律近乎 100% 正确。
- 缺点：工程量大，风格模仿弱，易写成语料拼贴。不适合起步，保留为将来"格律极致"的可选路线。

**C. 直接微调**

- 56 首不足，结果偏向背诵而非风格。等语料达到数百首后再作为 A 的升级选项。

**决定：采用 A。** 校验器设计为独立模块，将来 B 或 C 都能接入。

### 6.2 总体数据流

```
白话描述 + 体裁 (+ 词牌/谱)
        │
        ▼
  组装提示词（风格卡 + 示例 + 体裁规格 + 输出格式）
        │
        ▼
     调用模型  ──► 结构化输出（JSON）
        │                 │
        │                 ▼
        │           格律校验器
        │                 │
        │        ┌────────┴────────┐
        │        │ 通过            │ 不通过（≤N 次）
        │        ▼                 ▼
        │     输出 + 报告      把错误清单回传，重试
        │                          │
        └──────────────────────────┘
                     │
                     ▼
          用户取舍 → 落盘语料 / 运行日志
```

### 6.4 生成流程

1. 解析请求：体裁（古体 / 五律 / 七律 / 五绝 / 七绝 / 词）、词牌、白话内容、可选约束（韵部、情感、长度）。
2. 载入 `style/style-card.md` 与种子示例。v1 全量放入；语料超过阈值后改为按相关度选取 top-k（见 §9）。
3. **先算硬约束，再交给模型**（见 §6.9）：诗确定首句是否入韵、选定新韵韵部、取出候选韵字；词取出词牌谱与中华新韵对应韵部。这些显式写进提示词，不指望模型自己"记得"韵书。
   - 默认值（可用参数覆盖）：首句入韵默认开启；韵部优先取风格卡的用韵习惯，其次取语料中同体裁的高频韵部，再退回按音调随机；词按谱的韵位音调筛选韵部。
   - "律诗/绝句"必须在请求时明确五言或七言，不猜。
4. 组装提示词，要求模型输出固定 JSON：

```json
{
  "title": "题目",
  "genre": "七律",
  "cipai": null,
  "lines": ["第一句", "第二句"],
  "rhyme": ["韵脚字", "..."],
  "notes": "可选说明"
}
```

5. 解析并校验。
6. 若失败且未达上限，把 `errors` 列表原样回传，要求只改错处、保留已合规部分。
7. 输出诗歌、校验报告、剩余警告；同时写入 `runs/`。
8. 用户确认或修改后，写入 `corpus/poems/`。

### 6.5 校验规则

**句长与结构（诗）**

- 古体：句数不限；句长默认五言或七言，可按请求指定（如《游中原》式四言）。
- 律诗：五律/七律，8 句，每句 5/7 字。
- 绝句：五绝/七绝，4 句。
- "律诗/绝句"在 v1 只约束句数与字数，不约束平仄，实质是按该体裁的外形写。

**句长与结构（词）**

- 按词牌谱的段数、句数、每句字数逐项比对。

**平仄**

- 诗：**不校验**。粘对、孤平、三平调、拗救均不出现在错误清单里。
- 词：按谱中 `平 / 仄 / 中` 逐字比对；"中"跳过。
- 多音字：按**整句上下文的最常用读音**（pypinyin 默认读音）定平仄，不为了合谱改用生僻读音；最常用读音不合谱判错误，让模型改写该句。

**押韵（诗）**

- 中华新韵（十四韵），按普通话韵母归部；声调不限，平声、仄声都可作韵脚。
- 偶数句必须押韵，首句可押可不押；不得出韵、不得重韵。
- 古体：从宽——允许换韵、允许邻韵通押；句数不限（五古/七古；杂言与乐府 v1 不做）。
- 绝句：同律诗押韵规则（偶数句押韵）。
- 多音字：不是逐字独立判断，而是**在整首范围内求一组自洽的读音**。若有多种解，优先选常用读音，并在报告中标注"多音字，按 X 读"。

**押韵（词）**

- 中华新韵（十四部），按谱标记的韵位与平仄（平韵/仄韵/换韵）。
- 同一韵段内一韵到底；谱标"换韵"处换部。谱中只写"（韵）"而未标平仄时，默认跟随该词牌常用体；无法判断则向用户确认，不猜。
- 不再区分入声；入声字按现代普通话读音归入平或仄。这是"现代新韵"路线的有意取舍。
- 韵脚字查不到或无法判定读音，判错误（见 §6.10）。

**对仗**

- 诗：v1 不检查对仗。

**词牌谱**

- 存储为 YAML：词牌名、段（上/下阕）、每句的平仄串与韵标记。
- 输入解析支持常见写法：`平` `仄` `中`/`⊙`，行内 `（韵）`/`（句）`，换韵可用 `（换韵）` 或独立字段标注。
- 解析失败必须给出定位明确的错误，不接受"猜"。

### 6.6 风格卡

首次由脚本生成，之后人工可改。内容：

- 常用字与高频词
- 意象域（自然、器物、时序、情感）
- 句法偏好（倒装、省略、对句密度）
- 情感基调与常见转折方式
- 用韵习惯（偏爱哪些韵部）
- 忌用词 / 不喜欢的表达
- **默认全部 56 首作品**（也可用 `--max-examples N` 只取 N 首精选）
- 提示词中明确要求：学习用词、意象、句法、情感与转折方式，**不整句照抄**原作；与题目无关的原句不复用
- 生成后做**整句查重**：与种子中任一整句完全相同，判错误并带错误重试

生成方式：对 56 首做字频/句长/韵脚统计，再让模型归纳成结构化文字，二者合并，先写入 `style/style-card.draft.md`。

**人工审查（必须有）**：`style review` 展示草稿，用户可以：
- 回车接受；
- 用编辑器直接改；
- 输入修改意见，让模型多轮重写。

确认后才写入 `style/style-card.md`；生成只读这份已确认的卡，避免把模型的一次性归纳当成事实。

### 6.7 语料沉淀

- `corpus/poems/` 每条含 frontmatter：日期、体裁、词牌、韵部、状态（draft/final）、来源（seed/generated/edited）。
- **编辑流程**：生成结果先写成 `runs/<run-id>/draft.md`；用户用任意编辑器修改后运行 `accept <run-id>`；工具读回改动，保存原文、改后文与 diff。v1 不做编辑器内嵌。
- `runs/` 保存所有尝试与校验报告——这是将来微调最真实的数据（模型错在哪、人怎么改）。

### 6.8 模型适配

- `llm.py` 只暴露 `complete(messages, **opts) -> str`。
- 配置：`base_url`、`api_key`、`model`、`temperature`、`max_tokens`、超时、`backend`。
- `backend = "openai"`：兼容 OpenAI Chat Completions 协议；DeepSeek、OpenAI 等走这条。
- `backend = "ollama"`：走 Ollama 原生 `/api/chat`，固定 `think=false` 且用 JSON schema 约束输出。原因是 `qwen3.5:4b` 这类思考模型在 OpenAI 兼容 `/v1` 下会把输出预算耗在思考上，`content` 为空；原生接口能正确关闭思考。
- **配置档案（profile）**：`config.toml` 可写多套 `[models.<name>]`。v1 预置 `deepseek`（DeepSeek V4.1）与 `local`（qwen3.5:4b）两个档案。
- `generate` 用 `--profile` 选择；`compare` 对同一请求依次跑多个 profile，并排输出诗歌与校验报告。
- API Key 只从配置文件或环境变量读取，不写进仓库。
- 不在代码中写死任何厂商。

### 6.9 硬约束前置（重要）

校验器不只是"事后打分"，它同时是"事前给条件"。每次生成前，工具先算出：

- 诗：首句是否入韵、要用新韵哪个韵部，以及**该韵部的候选韵字表**；不生成平仄骨架。
- 词：词牌谱、每个韵段的平/仄/韵部，以及候选韵字。

这些直接写进提示词。理由：通用大模型对中华新韵与词牌谱的记忆不可靠，把韵书与词谱事实交给代码（厚资产），模型只负责在约束内遣词造句（薄模型）。

### 6.10 韵书数据层

**诗、词共用（中华新韵）**

- 以普通话拼音的韵母归部（十四韵），不涉简繁转换。
- 押韵：多音字用拼音库的词语/句子上下文取音；取不准时报错并列出候选读音，不静默取第一个。
- 词的平仄：同一套拼音读音，1/2 声为平，3/4 声为仄；轻声或取不准时报错，不静默归仄。
- 不建繁体字表，不做简繁消歧；输出与语料统一简体。
- 查不到的字：判为**错误**，不跳过——静默跳过会让校验结果失真。
- **取舍说明**：现代新韵没有入声，部分传统词牌的入声韵会按现代读音重新归部；这是用户明确选择的"现代新韵"路线，换来与诗一致的韵书和更低的维护成本。

### 6.11 词的句读单位

- 一个 `lines` 元素 = **词牌谱中的一行**（一个韵句/句读单位）。行内可以带逗号、顿号；校验时先去掉标点再逐字比对，标点不计入字数。
- 领字、句中逗属于该行，不单独拆成新的 `lines` 元素；换韵按谱在该行或该段上标注。
- 谱子按同一单位逐行给出；上下阕用 `sections` 分组。
- 解析器同时接受常见写法（`平/仄/中/⊙`、`（韵）`、`△/▲`、`可平可仄`），内部归一化为自有 DSL；解析失败报明确位置。
- 用户实际粘贴的谱子是最终标准；实现时需用 2–3 个真实例子（含《水调歌头》《菩萨蛮》《西江月》这类有逗、领字、换韵的）做验收。
- 预置词牌允许一个词牌存多个"体"（variant）。默认体优先选用户语料中已出现的体（如江城子取单调 35 字，而非双调 70 字）；没有语料依据时取最常用正体。用户粘贴的谱可新增或覆盖某个体。

### 6.12 风格验收

- 风格卡本身必须经 §6.6 的人工审查/多轮修改后才生效；生成只读已确认的卡。
- v1 以**人工阅读**为准，辅以一个可选的盲评小工具（同一请求生成 A/B 两版，隐藏来源，用户选更像自己的）。
- 不做自动风格评分。理由是自动指标容易优化成"像语料"而非"像人"，反而误导调参。
- "稳定"的验收口径：同一请求重复 5 次，至少 3 次在人工快速判断下"像用户"，且硬校验全部通过。

## 7. 待定与风险

1. **多音字**：诗、词都用拼音库。诗在整首范围内求自洽韵部；词按整句上下文取最常用读音定平仄，不为了合谱改用生僻读音。取不准或仍不唯一则报错并列出候选，不静默取第一个。
2. **词谱符号不统一**：用户可能用 `⊙`、`中`、`可平可仄` 混写。需要一个小而严格的 DSL，并在错误信息里给出正确示例。
3. **模型"顽固"**：同一处反复出错时，退化为"只重写问题句"；词在提示中给出该句的词牌平仄骨架。
4. **对仗**：v1 不检查，生成结果可能对仗不工；用户已接受这一取舍。
5. **数据来源**：中华新韵可由拼音韵母生成；词平仄用同一套拼音，不需要额外字表；词牌谱先预置常见十余调，其余由用户粘贴。
6. **风格卡漂移**：风格卡是用户可编辑的事实来源，生成时以卡片 + 示例为准，不从历史生成结果反向学习（避免自我污染）。

## 8. 成功标准

- 给定 56 首种子，用白话请求 + 体裁：诗能在 ≤3 次内产出通过押韵与句数/字数校验的作品；词能在 ≤3 次内通过词牌谱与中华新韵的完整校验。
- 同一请求重复多次，风格特征（高频词、意象、句法）稳定接近风格卡描述。
